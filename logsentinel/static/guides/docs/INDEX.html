LogSentinel project guide

LogSentinel makes authentication activity easier to investigate. Import Linux or Windows files, review five rule-based detections, and follow each alert to its source evidence.

The reproducible demo contains 85 events, four hosts, and five alerts. Every result comes from the same parser and detection engine used for uploads.

Try the working product

  1. Follow the README setup.
  2. Open the local workspace and select Load demo.
  3. Open an alert and inspect a source record.

The application has a dashboard, a searchable log explorer, and an investigation view. This guide explains the implementation behind those screens.

Follow one record through the system

Start with How it works. It maps actual Linux and Windows fields through UTC normalization, duplicate control, storage, correlation, and evidence review.

Each scenario includes source records, an identity key, thresholds, a timeline, an engine-verified result, normal explanations, and analyst recommendations.

Read the synthetic SSH case study for a concise technical report. It separates verified observations, hypotheses, missing evidence, and suggested checks.

Review the engineering choices

  • Architecture: separate modules, atomic transactions, replay, and stable identities.
  • Formats and source validation: supported inputs and what declared source fields can establish.
  • Security model: loopback-only operation, plaintext data, and no authentication.
  • Validation: tests actually executed, plus unverified environments.
  • Review follow-up: previous findings compared with the current implementation.
  • Portfolio presentation: a short English description and a Turkish presentation narrative.

This project demonstrates file-based analysis and explainable rule behavior. It does not measure production detection accuracy or establish its author's employment or learning history.
